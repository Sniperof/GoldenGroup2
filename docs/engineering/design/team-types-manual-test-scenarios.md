# سيناريوهات الاختبار اليدوي — أنواع الفرق (DEC-026)

> **الفرع:** `feat/team-types`
> **التاريخ:** 2026-11-24
> **المرجع:** `docs/constitution/decisions/DEC-026-team-types.md`، وخطة التنفيذ `team-types-implementation-plan.md`

## 1. بيئة الاختبار

الاختبار يجري على **قاعدة اختبار محلية** نسخة من `golden_crm_srv`، فلا يمس بيانات العمل ولا الـ staging.

| البند | القيمة |
|---|---|
| القاعدة | `golden_crm_teamtypes_test` |
| الهجرات المطبقة عليها | 505، 506، 507 |
| الواجهة | `http://localhost:5001` (أو 5000 إن كان المنفذ حراً) |
| الـ API | المنفذ 3000، بإعداد التشغيل `api-teamtypes-test` |

### تجهيز البيئة من الصفر

| الخطوة | الأمر أو الإجراء |
|---|---|
| 1. نسخ القاعدة (لا اتصالات مفتوحة على المصدر) | `CREATE DATABASE golden_crm_teamtypes_test TEMPLATE golden_crm_srv;` |
| 2. تطبيق الهجرات على النسخة فقط | ملفات `migrations/505_*.sql` و`506_*.sql` و`507_*.sql` |
| 3. تجهيز بيانات الاختبار | `DATABASE_URL=<رابط قاعدة الاختبار> npx tsx packages/api/seed-team-types-scenarios.ts` (من مجلد `packages/api`) |
| 4. تشغيل الـ API على قاعدة الاختبار | إعداد `api-teamtypes-test` في `.claude/launch.json` |
| 5. تشغيل الواجهة | `pnpm run dev:web` |

السكربت في الخطوة 3 يرفض العمل على أي قاعدة غير `golden_crm_teamtypes_test`.

> ⚠️ ما دام API الاختبار يعمل على المنفذ 3000، فأي واجهة محلية أخرى تتصل بالمنفذ نفسه ترى بيانات الاختبار. أوقفه بعد الانتهاء.

## 2. الحسابات

كلمة المرور واحدة لكل الحسابات، وهي في الثابت `TEST_PASSWORD` داخل `packages/api/seed-team-types-scenarios.ts`. تعمل على قاعدة الاختبار فقط، ولا تغيّر شيئاً في الحسابات الحقيقية.

| المستخدم | الشخص | الدور | الاستخدام |
|---|---|---|---|
| `superadmin` | مدير النظام | سوبر أدمن | شاشة أنواع الفرق (الكتالوج) |
| `Said2` | سعيد عبد المنعم عمر | مدير فرع 1001 | الجدولة، وأنواع الفرع، وتوزيع المسارات، والفريق الرديف |
| `BManED` | — | مدير فرع 1002 | التحقق من عزل الفروع |
| `LANA` | لانا نبيل حجازي | مشرفة خدمة زبائن | رئيسة فريق التحصيل التجريبي |
| `AdminMN` | محمد اسامة النقلي | تلماركتر | مسوق فريق التحصيل |
| `TlmMR` | مايا امير الريحاوي | تلماركتر | مسوقة الفريق القياسي |
| `Abeer` | عبير محمود الشيخ | مشرفة خدمة زبائن | رئيسة الفريق القياسي |

> كلمة مرور `LANA` و`AdminMN` و`TlmMR` و`Abeer` تُضبط عند تشغيل جولة الاختبار الآلية. في نسخة جديدة تُضبط بالدالة `setTestPasswordForEmployee` من ملف الـ seed نفسه.

## 5. نقاط معروفة قبل الاختبار

| النقطة | التفصيل |
|---|---|
| رئيس فريق من دور «مشرفة خدمة زبائن» | الدور يملك `telemarketing.lists.view_device_demo` فقط، فلا يرى كشوف التحصيل. يحتاج منح `telemarketing.lists.view` أو اختيار دور آخر للرئيس. قرار منح، لم يُعدَّل |
| بوابة القسم (DEC-009 R-10) | مهمة جهاز لا تدخل نطاق الفريق إذا كان موديل الجهاز خارج موديلات قسم المشرف. سلوك سابق وصحيح |
| تقارير «زيارات المشرف/الفني» | تعدّ رئيس النوع المخصص «مشرفاً»، ولا تُظهر الخانات الميدانية الإضافية |
| نوع المهمة الجديد | لا يُضاف تلقائياً لأي نوع فريق، حتى القياسي، فيبقى الزبون الذي لديه هذا النوع خارج الفرق حتى يضيفه الأدمن |
